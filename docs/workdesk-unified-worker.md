# BOARD-9 Тред Борды и чат задачи Workdesk — одна лента

Порядок установки на macOS для уполномоченного оператора. Служба отправки не открывает сокет и получает записи из локальной очереди SQLite. Она опрашивает текущий claim через board-role и этим же адаптером вызывает `post_board_thread_message` или `report_task`. На обычном сервере Борды остаётся входящая обработка SSE.

1. Подтвердить два выделенных служебных UID с разными правами и одну закрытую группу для базы. UID автора записи обслуживает только доверенный нативный launcher и запись в очередь. UID отправителя получает board-role и доступ к очереди. Интерактивный UID не входит в группу. Процессы, выполняющие обычные команды агента, не должны получать право записи в эту базу.
2. Установить код и адаптер из согласованного Git-коммита в каталог, контролируемый администратором. Настроить отдельный каталог состояния для доверенной установки Борды. Владелец каталога и `board.db` — UID автора записи, группа — закрытая группа. Права каталога `0770`, базы `0660`. Обоим процессам нужен `umask 007`. До запуска проверить полные пути, ACL, права доступа к SQLite WAL/SHM и отсутствие возможности подменить каталог/файлы из интерактивного UID. Базу или очередь из каталога общего UID не переносить.
3. В защищённом конфиге указать `workdesk.unified` с локальным adapter executable/argv и объектом `isolation` с числовыми `writerUid`, `senderUid`, `interactiveUid`, `sharedGid`. Указать штатный `workdeskDialog` binding с текущей задачей, assignment, UUID локального треда и нативным SID. Права на конфиг и каталог кода исключают подмену команды, binding и UID интерактивной сессией. Workdesk-оператор провиженит ограниченный board-role для UID отправителя, держит секрет вне конфига Борды и argv и выдаёт его только адаптеру через утверждённое защищённое хранилище. В argv адаптера допускается защищённая ссылка или путь, не значение bearer. Проверить каталог board-role в контексте службы, включая `list_board_tasks`, `post_board_thread_message`, `report_task`, и текущий claim.
4. До подключения отправителя подтвердить нативное удостоверение того же SID и открытого локального треда в изолированном окружении автора. Инструмент нативного MCP должен быть недоступен обычному UID. Флаг в конфиге, имя pane и копия общей SQLite не удостоверяют происхождение. До выполнения этого пункта службу отправки не запускать.
5. Для `/Library/LaunchDaemons` подготовить root-owned plist с `Label=com.mokuteam.board-workdesk-sender`, `UserName` отправителя, `GroupName` закрытой группы, `Umask=7` (целое), `RunAtLoad=true`. В `ProgramArguments` задать абсолютный путь к установленному Bun, `--no-env-file` и абсолютный путь к `src/entrypoints/workdesk-unified-worker.ts`. В `EnvironmentVariables` указать только пути `APPDATA` и `LOCALAPPDATA` по раскладке `src/adapters/paths.ts`. Оператор проверяет plist через `plutil -lint`, устанавливает его `root:wheel` с режимом `0644` и запускает `launchctl bootstrap system /Library/LaunchDaemons/com.mokuteam.board-workdesk-sender.plist`. Состояние показывает `launchctl print system/com.mokuteam.board-workdesk-sender`. Не назначать `KeepAlive` до проверки штатного запуска.
6. Откат отправителя — `launchctl bootout system/com.mokuteam.board-workdesk-sender` и отключение настройки `workdesk.unified` в изолированном экземпляре. Сохранить SQLite и её WAL при незавершённых операциях. Повтор сообщения использует тот же UUID idempotency, неопределённый результат `report_task waiting` сверяется оператором отдельно. Доступ к bearer отзывается уполномоченным Workdesk-оператором. Действующую Борду и её базу этот порядок не переключает.
